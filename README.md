# EKN Design Tokens Target

Static integration repository proving that CSS generated by `ekn-central-tokens` can be delivered to a target project and consumed without copying canonical JSON into application source.

This repository owns consumer imports, demo behavior, runtime scheme scope, and target-side checks. Read the [overall product architecture](https://github.com/phamtruonghoaithanh-ekino/ekn-design-tokens-personal/blob/main/docs/project/architecture.md) for the full system and the [Central artifact contract](https://github.com/kimbaole-ekino/ekn-central-tokens/blob/main/docs/artifact-contract.md) for generated output rules.

## Demos

- `src/demos/block/index.html` — multiple `data-color-scheme` values on independent page blocks.
- `src/demos/full-page/index.html` — one `data-color-scheme` value on `<html>` for an application-wide mode.
- `index.html` — comparison and artifact contract overview.

Both pages deliberately use the same semantic CSS variables and content pattern. The difference is only where the scheme attribute is owned.

## Delivered artifact layout

Central delivery currently provides six generated schemes for one project:

```text
src/styles/tokens/ekn/css/creative-black.css
src/styles/tokens/ekn/css/creative-white.css
src/styles/tokens/ekn/css/cx-black.css
src/styles/tokens/ekn/css/cx-white.css
src/styles/tokens/ekn/css/health-black.css
src/styles/tokens/ekn/css/health-white.css
```

Do not edit these files manually. They are generated in Central Tokens and replaced through target pull requests. JSON and `manifest.json` remain central-only artifacts.

## Run locally

Use any static file server from the repository root. For example:

```sh
npx serve .
```

Then open the root page shown by the server. Opening HTML directly through `file://` also works for the current relative assets, but an HTTP server is preferred because it matches deployment behavior.

## Validate

Use Node 22:

```sh
npm test
npm run validate:demo
npm run validate
```

The checks verify that every delivered scheme supports both selector forms, required semantic variables exist, required demo assets exist, the block page contains local scopes, and the full-page demo contains only the root scope.

## Runtime decision

Use **block-scoped schemes** when one page needs mixed light/dark editorial sections, embedded previews, or component-level overrides. Use a **full-page scheme** when the application has one active mode and components should inherit it globally. Supporting both selectors in generated CSS does not mean every product must use both strategies; each target should document its chosen ownership rule.
